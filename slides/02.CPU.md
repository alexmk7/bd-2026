# Общая архитектура компьютера фон Неймана

![bg width:380px right:30%](https://upload.wikimedia.org/wikipedia/commons/d/d8/ABasicComputer.gif)

Классическая модель:

- **CPU** (процессор)
- **RAM** (оперативная память)
- Постоянное хранилище (HDD / SSD)
- Устройства ввода-вывода
- **Шина** (system bus) — связывает всё вместе

---

# Основные компоненты CPU

- **Регистры** — сверхбыстрая память внутри процессора
- **ALU** (арифметико-логическое устройство)
- **Control Unit** (устройство управления)
- **Кэш-память** (L1, L2, L3)
- **MMU** (Memory Management Unit) — блок управления памятью

Основной цикл работы процессора:  
**Fetch → Decode → Execute**

---

# Регистры и Instruction Pointer (RIP)

Регистры — самая быстрая память в компьютере

Пример (x86-64):

```asm
mov $5,  %rax       # rax ← 5
mov $3,  %rbx       # rbx ← 3
add %rbx, %rax      # rax ← rax + rbx
```

**RIP** (instruction pointer) — указывает на **следующую** выполняемую инструкцию

---

# Память CPU: иерархия скоростей

Проблема: RAM намного медленнее регистров.

| Уровень     | Размер (примерно) | Время доступа     | Кто использует    |
|-------------|-------------------|-------------------|-------------------|
| Регистры    | сотни байт        | ~0.1–0.5 нс       | CPU               |
| L1-кэш      | 32–128 KiB        | ~0.5–1 нс         | ядро              |
| L2-кэш      | 256 KiB – 2 MiB   | ~3–10 нс          | ядро              |
| L3-кэш      | 4–128 MiB         | ~10–40 нс         | все ядра          |
| RAM         | 8–256 GiB         | ~50–120 нс        | вся система       |
| SSD         | сотни GiB–TiB     | ~20–100 мкс       | ОС                |
| HDD         | —                 | ~5–10 мс          | ОС                |


---

# Как работает кэш-память

Кэш загружает данные **блоками** — **cache line** (обычно 64 байта)

- Чтение 1 байта → загружается целых 64 байта
- Принцип локальности (temporal + spatial)

---

# Доступ CPU к памяти

Последовательность типичного обращения:

1. CPU выдаёт **виртуальный** адрес
2. Проверка в **L1** → **L2** → **L3**
3. Cache hit → быстрое чтение
4. Cache miss → запрос в RAM через **MMU** и шину
5. Данные возвращаются + заполняется кэш

---

# Виртуальная и физическая память

![width:420px center](https://upload.wikimedia.org/wikipedia/commons/thumb/3/32/Virtual_address_space_and_physical_address_space_relationship.svg/960px-Virtual_address_space_and_physical_address_space_relationship.svg.png)

- Программы видят **виртуальные адреса**
- **MMU** переводит их в **физические адреса**
- Основа: изоляция процессов, виртуальная память

---

# Что происходит при включении компьютера

1. Подача питания
2. CPU стартует с фиксированного адреса (обычно 0xFFFFFFF0)
3. Запускается **firmware** (BIOS / UEFI)
4. Firmware → POST → поиск загрузочного устройства
5. Загрузка **bootloader**
6. Bootloader → загрузка ядра ОС
7. Ядро инициализирует систему → запуск systemd

---

# Уровни загрузки подробнее

**Firmware** (BIOS/UEFI)  
→ проверка оборудования, инициализация, выбор boot device

**Bootloader** (GRUB, systemd-boot, Windows Boot Manager)  
→ загрузка ядра в память, передача управления

**Ядро ОС**  
→ инициализация памяти, драйверов, планировщика  
→ запуск первого процесса (обычно **systemd** в Linux)

---

# Программа → машинный код

Исходный код → компилятор/ассемблер → **машинный код**

Пример:

```asm
mov $1, %rax
```

→

```
48 C7 C0 01 00 00 00
```

CPU исполняет именно **последовательность байт**

---

# Организация памяти процесса

Типичная раскладка (виртуальная память процесса):

```
Высокие адреса  ┌──────────────────┐
                │      Stack       │ ← rsp
                ├──────────────────┤
                │       ...        │
                ├──────────────────┤
                │       Heap       │ ← растёт вверх
                ├──────────────────┤
                │   Data + BSS     │
                ├──────────────────┤
Низкие адреса   │      Code        │
                └──────────────────┘
```

---

# Stack и Heap в деталях

**Stack**  
- LIFO-структура  
- Локальные переменные, аргументы, адрес возврата  
- `push`, `pop`, `call`, `ret`

**Heap**  
- Динамическое выделение памяти  
- `malloc / free`, `new / delete`  
- Управляется библиотекой или языком

---

# Что такое операционная система

**ОС — это программа-посредник**, которая:

- Управляет аппаратными ресурсами
- Предоставляет удобный интерфейс программам
- Обеспечивает изоляцию и безопасность

Главные задачи ОС:
- Управление процессором
- Управление памятью
- Управление устройствами ввода-вывода
- Управление файлами

---

# Основные компоненты ОС

- **Ядро** (kernel) — центральная часть
- Планировщик процессов (scheduler)
- Менеджер памяти
- Подсистема ввода-вывода + драйверы
- Файловая система
- Интерфейс системных вызовов (syscall)

---

# Режимы работы процессора

- **Kernel mode** (привилегированный) — полный доступ к железу
- **User mode** — ограниченный доступ, обычные программы

Переход из user → kernel происходит через **системные вызовы**

Примеры: `read()`, `write()`, `fork()`, `mmap()`, `open()`

---

# Процесс и потоки

**Процесс** = программа в состоянии выполнения  
Содержит: код, данные, heap, stack, открытые файлы, регистры...

**Поток** (thread) = единица планирования внутри процесса  
- Делят код, данные, heap  
- Имеют собственные регистры и стек

---


# Планировщик и многозадачность

Планировщик решает, какой процесс/поток получает CPU в данный момент.

**Context switch**:
- Сохранение регистров текущего процесса
- Загрузка регистров следующего процесса
- Переключение стека, %rip и т.д.

Создаётся иллюзия одновременного выполнения

---

# Виртуальная память и страничная организация

Каждый процесс видит **своё собственное** адресное пространство 0…N

- Память делится на **страницы** (обычно 4 KiB)
- **Page table** — таблица отображения виртуальных страниц → физические
- **MMU** выполняет трансляцию автоматически
