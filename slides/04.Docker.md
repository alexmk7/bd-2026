# Что такое виртуализация?

**Виртуализация** —это создание изолированных виртуальных сред на одном физическом хосте.

**Преимущества:**
- Эффективное использование железа
- Изоляция приложений
- Быстрое клонирование и восстановление
- Снимки состояния (snapshots)

---

**Недостатки:**
- Высокий расход ресурсов
- Каждая виртуальная машина содержит полную ОС
- Медленный запуск

---

# Типы гипервизоров

**Гипервизор** — программа, создающая и управляющая виртуальными машинами.

| Тип                  | Описание                              | Примеры                          | Overhead    |
|----------------------|---------------------------------------|----------------------------------|-------------|
| **Type 1 (Bare-metal)** | Работает напрямую на железе          | KVM, VMware ESXi, Xen, Hyper-V  | Низкий     |
| **Type 2 (Hosted)**     | Работает поверх хостовой ОС          | VirtualBox, VMware Workstation   | Высокий    |

**KVM** — самый популярный гипервизор в Linux (встроен в ядро).

---

# Достоинства и недостатки гипервизоров

**Type 1 (Bare-metal):**
- **+** Высокая производительность
- **+** Лучшая безопасность
- **–** Сложнее установка

**Type 2 (Hosted):**
- **+** Удобен для разработки и тестирования
- **+** Легко установить на обычный ПК
- **–** Дополнительные накладные расходы

---

# Контейнеры vs Виртуальные машины

**Виртуальная машина**          | **Контейнер**
--------------------------------|----------------------
Полная гостевая ОС внутри       | Только приложение + библиотеки
Размер: несколько ГБ            | Размер: десятки МБ
Запуск за минуты                | Запуск за секунды
Высокие накладные расходы       | Минимальные накладные расходы

**Контейнер** — это изолированный процесс, а не полноценная машина.

---

# Основные механизмы ядра Linux для контейнеров

Docker использует возможности ядра Linux:

- **Namespaces** — изоляция ресурсов:
  - PID, Network, Mount, User, UTS, IPC и др.
- **Cgroups** — ограничение и учёт ресурсов (CPU, память, I/O)
- **Union Filesystems** (overlay2) — слоистая файловая система
- **Capabilities & Seccomp** — ограничение прав процесса

**Примеры использования:**
- `unshare`, `systemd-nspawn`
- Все современные контейнерные технологии (Docker, Podman, containerd)

---

# Принципы Docker

**Docker** — платформа для разработки, доставки и запуска приложений в контейнерах.

**Основные понятия:**
- **Image (образ)** — неизменяемый шаблон для запуска контейнеров
- **Container (контейнер)** — запущенный экземпляр образа
- **Registry (реестр)** — хранилище образов (Docker Hub, GitHub CR и др.)
- **Repository (репозиторий)** — коллекция связанных образов (например, `python`, `nginx`)

# Создание образа. Dockerfile (Python)

**Dockerfile** — инструкция по сборке Docker-образа.

```dockerfile
# Пример Dockerfile для Python-приложения
FROM python:3.12-slim

# Создаём рабочую директорию
WORKDIR /app

# Сначала копируем только зависимости — для лучшего кэширования
COPY requirements.txt .

# Устанавливаем зависимости
RUN pip install --no-cache-dir -r requirements.txt

# Копируем остальной код приложения
COPY . .

# Открываем порт (если нужно)
EXPOSE 8000

# Команда запуска по умолчанию
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

---

# Сборка образа

```bash
# Простая сборка
docker build -t mypythonapp:1.0 .

# Сборка с указанием файла
docker build -t mypythonapp:1.0 -f Dockerfile.prod .

# Игнорирование кэша
docker build --no-cache -t mypythonapp:1.0 .
```

---

# Запуск контейнера

```bash
docker run -d --name myapp \
  -p 8080:8000 \                    # проброс портов
  -v $(pwd):/app \                  # монтирование кода (для разработки)
  --restart unless-stopped \
  mypythonapp:1.0
```

**Проброс портов:**
- `-p 8080:8000` — порт 8080 на хосте → порт 8000 внутри контейнера
- Порт — это числовой идентификатор сетевого соединения (0–65535)

**Общие папки (Volumes):**
- `-v /host/path:/container/path` — монтирование папок

---

# Работа с контейнером

**Основные команды:**

```bash
docker ps                    # запущенные контейнеры
docker ps -a                 # все контейнеры
docker logs myapp -f         # просмотр логов
docker exec -it myapp bash   # зайти внутрь контейнера
docker stop myapp
docker start myapp
docker rm -f myapp           # удалить контейнер
```

# Docker Compose

```yaml
services:
  app:
    build: .
    ports:
      - "8080:8000"
    volumes:
      - .:/app
    environment:
      - DEBUG=True
    depends_on:
      - db

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: mydb
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:
```

---


**Запуск:**
```bash
docker compose up -d
docker compose down
```

# Продвинутая сборка

**Рекомендации по оптимизации:**

1. **.dockerignore** — исключать ненужные файлы (`__pycache__`, `.git`, `venv`)
2. **Многоэтапная сборка (multi-stage):**
   ```dockerfile
   FROM python:3.12 AS builder
   RUN pip install -r requirements.txt
   COPY . .
   RUN python -m build

   FROM python:3.12-slim
   COPY --from=builder /app/dist/*.whl .
   RUN pip install *.whl
   ```
3. **Кэширование слоёв** — размещать редко меняющиеся инструкции сверху

---

4. **Build arguments:**
   ```dockerfile
   ARG ENV=production
   ENV ENV=${ENV}
   ```
5. **BuildKit** — современный движок сборки (включён по умолчанию)
