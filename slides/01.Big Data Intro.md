# Теория и практика больших данных
## Вводная лекция

---

# Что такое данные?

**Данные** — это формализованное представление информации, пригодное для хранения, передачи и обработки.

Примеры:

- таблица пользователей
- банковские транзакции
- логи сервера
- изображения
- видео
- показания датчиков
- тексты для обучения LLM

---

# Данные вокруг нас

Источники данных:

- веб-сайты
- мобильные приложения
- банковские системы
- научные эксперименты
- IoT устройства
- социальные сети

---

# Рост количества данных

Рост экспоненциальный:

| Год | Объем |
|----|------|
| 1980 | MB |
| 1990 | GB |
| 2000 | TB |
| 2010 | PB |
| 2020 | EB |
| 2030 | ZB |

---

# Почему данных стало много?

Причины:

- интернет
- смартфоны
- дешевые диски
- облачные вычисления
- социальные сети
- IoT

---

# Когда появился термин Big Data?

Первые упоминания:

- 1997 — NASA
- 2001 — Doug Laney (3V)
- 2004 — Google MapReduce
- 2006 — Google BigTable
- 2008 — Hadoop

---

# Почему традиционные системы перестали справляться?

Проблемы:

- слишком большой объем
- слишком высокая скорость
- слишком сложная структура

---

# Определение Big Data

Big Data — данные, которые:

- слишком большие
- слишком быстрые
- слишком сложные

для обработки традиционными на начало 2000-х методами

---

# Эволюция хранения данных

4 этапа:

1. Файлы
2. Реляционные БД
3. NoSQL
4. Distributed systems

---

# Этап 1: Файлы

1960–1980

Проблемы:

- сложно искать
- нет структуры
- нет индексов

---

# Этап 2: Реляционные базы данных

1970–настоящее время

Модель: таблицы

Пример:

| id | name | age |
|----|------|-----|

---

# SQL — язык работы с данными

* простота
* мощный язык
* стандартизация
* надежность

---

# Ограничения SQL (классических реляционных БД)

Проблемы:

* плохо масштабируется
* сложно хранить JSON, видео
* дорого масштабировать

---

# Вертикальное масштабирование

Увеличение памяти, диска, CPU

Ограничение: есть физический предел

---

# Горизонтальное масштабирование

Горизонтальное масштабирование: больше серверов.

Основа Big Data

---

# Этап 3: NoSQL базы данных

NoSQL = Not Only SQL

Появились: 2000+

Причины:

* большие данные
* распределенные системы

---

# Типы NoSQL

4 основных типа:

* Key-value
* Document
* Column
* Graph

---

# Key-Value

Структура:

```
key → value
```

Пример:

```
"user:123" → "Alex"
```

---

# Document database

Пример:

```json
{
  "name": "Alex",
  "age": 25
}
```

Гибкая схема

---

# Column database

Хранение по колонкам

Преимущество:

* быстро для аналитики

---

# Graph database

Структура:

```
Node → Edge → Node
```

Используется:

* социальные сети
* рекомендации

---

# Distributed systems

Идея:

использовать много компьютеров

вместо одного большого

---

# Distributed storage

Пример:

```
File:
part1 -> server1
part2 -> server2
part3 -> server3
```

---

# Distributed computing

Идея:

```
Task:
part1 -> server1
part2 -> server2
part3 -> server3
```

---

# Характеристики Big Data: 3V

Doug Laney, 2001

* Volume
* Velocity
* Variety

---

# Volume — объем

Пример:

* миллиарды записей
* петабайты данных

---

# Velocity — скорость

Пример:

* биржи
* сенсоры
* онлайн игры

---

# Variety — разнообразие

Типы данных:

* таблицы
* текст
* изображения
* видео

---

# Дополнительные V

5V модель:

* Volume
* Velocity
* Variety
* Veracity
* Value

---

# Veracity — достоверность

Проблемы:

* ошибки
* шум
* пропуски

---

# Value — ценность

Цель:

получить пользу из данных
